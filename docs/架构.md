# 架构

## 定位

别名数据层：把「别名 ↔ 标准名」的关系收在一处，对外开放查询。**不接管业务**——
图库目录检查、页面路由、业务归一、加权评分、用户命令都归调用方。

## 目录分层

```
Alias-Plugin/
├── index.js              入口：配置兜底 + 日志头 + 装配 apps/（不含业务逻辑）
├── apps/
│   └── aliasService.js   能力出口：一个继承 plugin 的类，挂载查询方法（无 rule / task）
├── modules/
│   ├── AliasService.js   业务出口：查询、清单、状态、重建、降级
│   └── HotReload.js      data/ 目录监听 → 防抖 → 重建索引
├── model/
│   ├── AliasFile.js      数据文件读取（只读，失败降级）
│   └── AliasIndex.js     索引构建与查询（纯内存，零 I/O）
├── components/
│   ├── normalize.js      文本归一化与别名串拆分（纯函数）
│   ├── sources.js        游戏 / 实体 / 来源的唯一定义处
│   └── config.js         三层配置读取 + pluginRoot
├── data/                 别名数据（入库）
├── defSet/config.yaml    配置模板（占位符）
├── config/config.yaml.example  配置参考（入库）
├── scripts/sync-alias.mjs      数据生成脚本
├── test/                 回归套件
└── docs/
```

依赖方向单向：`index.js → apps → modules → model → components`。`components` 不 import 上层。

## 数据流

```
上游文件（只读）                       自维护
plugins/miao-plugin/…/alias.js         data/custom.json
plugins/ZZZ-Plugin/defSet/alias.yaml        │
        │                                    │
        └──────── scripts/sync-alias.mjs ─────┘
                          │
                          ├─→ data/alias.json    运行时唯一真相（条目数组）
                          └─→ data/source.json   上游内容哈希（Action 比对用）
                          │
        model/AliasFile.js 读 → model/AliasIndex.js 建表 → modules/AliasService.js 查询
```

## 数据文件结构

`data/alias.json`（生成物，**不手工编辑**）：

```json
{
  "version": 1,
  "generatedAt": "2026-10-15T00:00:00.000Z",
  "entries": [
    { "canonical": "胡桃", "alias": "核桃", "game": "gi", "entity": "character", "src": "miao" }
  ]
}
```

`data/source.json`：每个上游文件的 `src / game / entity / file / bytes / sha256`，供 `--check` 与 Action 判定。

## 来源与优先级

| 来源 | 含义 | 优先级 |
|------|------|--------|
| `miao` | miao-plugin 的 6 个别名文件（gs/sr × 角色/武器/圣遗物） | 10 |
| `zzz` | ZZZ-Plugin 的 `defSet/alias.yaml`（绝区零角色，值可为数组） | 10 |
| `custom` | `data/custom.json`，由其他插件解耦并入、本插件自维护 | 20 |

`custom` 与上游**同名标准名**时合并别名串（`scripts/sync-alias.mjs` 内完成）；
覆盖判定发生在查询期，按 `(归一键, 游戏, 实体)` 分组取最高优先级那一批。

## 归一化

只解决「同一个词的不同写法落到同一个键」：去空白 → 去间隔号（`·・•‧`）→ 去包裹符号
（`「」『』《》【】（）()[]""''`）→ 小写。**刻意不去花括号**（`{NICKNAME}` 是星铁开拓者的标准名）。

不做：命令前缀剥离、简繁转换、模糊匹配、目录名匹配。

## 缓存与刷新

- 索引**同步构建**、进程内缓存、懒加载：`build()` 里没有 `await`，因此不存在「并发读到半成品」的窗口
- 数据文件变更 → `modules/HotReload.js` 目录级 `fs.watch` + 文件级 `fs.watchFile(1000ms)` 双监听
  → 防抖（`reload.debounceMs`，默认 500ms）→ `reload()`
- `reload.watch: false` 时完全不挂监听
- 所有失败路径只 `logger.warn`，查询退化为「未命中」
