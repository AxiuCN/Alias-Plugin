# 数据与同步

## 上游（只读）

| 来源 | 文件 | 导出 / 形态 | 游戏 / 实体 |
|------|------|------------|------------|
| miao-plugin | `resources/meta-gs/character/alias.js` | `export const alias` | gi / character |
| miao-plugin | `resources/meta-gs/weapon/alias.js` | `alias` + `abbr` | gi / weapon |
| miao-plugin | `resources/meta-gs/artifact/alias.js` | `alias` + `setAbbr` | gi / artifact |
| miao-plugin | `resources/meta-sr/character/alias.js` | `alias` | hsr / character |
| miao-plugin | `resources/meta-sr/weapon/alias.js` | `alias` + `abbr` | hsr / weapon |
| miao-plugin | `resources/meta-sr/artifact/alias.js` | `alias` + `artiAbbr` | hsr / artifact |
| ZZZ-Plugin | `defSet/alias.yaml` | `{ 标准名: [别名…] }` | zzz / character |

读取方式：优先 `import()`（带 mtime 缓存破坏），失败回退「提取对象字面量 + 求值」。
**不修改上游任何文件**；上游的值既可以是逗号分隔字符串，也可以是数组，解析时统一拆分。

来源（miao / ZZZ / 自维护）**只影响生成期的合并，不进入产物、也不参与查询判定**。

## 自维护

`data/custom.json`：本插件自维护的别名（由其他插件解耦并入）。结构按 游戏 → 实体 → 标准名：

```json
{
  "gi": { "character": { "旅行者": "空,荧,主角,枪主,男主,女主" } },
  "hsr": { "character": { "{NICKNAME}": "开拓者,穹,星,主角,男主,女主,星穹列车开拓者" } },
  "zzz": { "character": { "星见雅": "雅" } }
}
```

规则：

- 值是逗号分隔字符串（与上游 miao 的写法一致）
- 与上游**同名标准名**时**合并别名串**，不覆盖——上游已维护的俗称不会消失
- 标准名里需要 `{}` 时照写（如 `{NICKNAME}`），归一化保留花括号

## 生成

```bash
cd plugins/Alias-Plugin
pnpm sync                     # = node scripts/sync-alias.mjs
node scripts/sync-alias.mjs --check   # 只比对，有变化 exit 1（CI / Action 用）
node scripts/sync-alias.mjs --bot=<bot根> --out=<数据目录>   # 覆盖路径（一般不用）
```

输出：`data/alias.json`（别名边表，**四个字段：canonical / alias / game / entity**）+ `data/source.json`（上游指纹）。
脚本**确定性**：排序 game → entity → 归一键 → 原文，重复执行不产生 diff；
`--check` 只比对 `entries` / `upstream`，忽略 `generatedAt`。

## 迁移其它插件的自维护别名

1. 从来源插件抄出「标准名 → 别名」映射（**不改来源仓库**）
2. 写进 `data/custom.json` 对应游戏 / 实体
3. `pnpm sync` 重新生成
4. 在 `docs/待办与规划.md` 登记接入进度
