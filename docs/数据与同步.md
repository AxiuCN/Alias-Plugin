# 数据与来源

## 运行期读本机，没有共享生成物

别名数据**全部在运行期从本机读取**：miao 是 Yunzai 的基础插件（人人都有），
ZZZ-Plugin 是选装（没装的也用不上 zzz 别名），实例自定义别名本来就各实例不同。
所以不存在"生成一份共享别名表分发给所有人"这件事。

| 位置 | 来源 | 在哪 | 性质 |
|------|------|------|------|
| 1 `preset` | miao-plugin 预设 | `<miao>/resources/meta-{gs,sr}/{character,weapon,artifact}/alias.js` | 随插件分发，只读 |
| 1 `preset` | ZZZ-Plugin 预设 | `<zzz>/defSet/alias.yaml` | 选装插件，只读 |
| 2 `overlay` | 本仓库自带 | `data/aliases.json`（入库） | 本仓库维护的公开别名 |
| 3 `custom` | 实例自定义 | `<miao>/config/alias_{gs,sr}.cfg` | **各实例私有**，运行期可被 `#喵喵别名` 改写 |

**实例自定义别名绝不写进本仓库的任何文件**——它是私有数据，进仓库就意味着把一个人的
别名分发给所有人。

## 上游文件的导出名不统一

miao 各文件的导出名是 `alias` / `abbr` / `setAbbr` / `setAlias` / `artiAbbr` /
`artiSetAbbr` / `aliasCfg` 混着来的，因此读取端**不按导出名取**：把文件里所有对象导出
合并（同名取并集），`import()` 失败时回退"提取对象字面量 + 求值"。

## 仓库自带 `data/aliases.json`

```json
{
  "version": 1,
  "aliases": [
    { "canonical": "旅行者", "alias": "空", "game": "gi", "entity": "character" }
  ]
}
```

- 与预设**同名原名**时合并别名（不覆盖），避免丢掉上游已维护的俗称
- **以后 GitHub Action 扒到的别名也写进这个文件的 `aliases` 数组**——
  运行期入口已经就位（文件存在就读、不存在就跳过），Action 落地时不需要改代码

## 实例自定义 cfg 的解析

格式与 miao 一致，每行一条：

```
胡桃：往生堂主
旅行者：空，荧
```

- 兼容中英文冒号与逗号 / 顿号；坏行跳过，不影响其他行
- 行首允许是**原名或已有别名**（与 miao 的 `getId` 语义一致）；解析不到就跳过该行并计数
  （见 `status().unresolvedCustom`）
- 命中后该原名升到 `custom` 位置：同一个写法上，它一票压过预设与仓库自带

## 配置

`defSet/config.yaml` + `config/config.yaml.example` 是配置三层结构的占位；当前插件
**没有任何配置项**（不做缓存、不联网、不注册命令），`components/config.js` 只推导插件根路径。
需要配置项时再往三层结构里加。

## 测试前置

套件通过 `ALIAS_MIAO_DIR` / `ALIAS_ZZZ_DIR` 指向 `test/.test-tmp/` 下的夹具目录，
**绝不读写真实的 miao / ZZZ 目录**（尤其不写它们的 `config/`）。生产不设这两个变量。
